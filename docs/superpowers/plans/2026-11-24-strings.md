# Strings Implementation Plan (1 of 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A library of about 60 real strings from 14 brands that people browse, open and search the way they do racquets, each shown as a spool in its own colour.

**Architecture:** Strings are data files (`strings/<brand>/<id>.json`) that `generate` gathers into `assets/strings.json`. One generated spool GLB is tinted at runtime. A single route parser replaces the scattered hash patterns, and the gallery gains a strings section beside the racquets.

**Tech Stack:** Bun, TypeScript, zod, three.js, Vite. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-24-strings-and-build-design.md`. Plan 2, the build page, is `2026-11-24-build-page.md` and needs this one first.

## Global Constraints

- Every existing file under `assets/` stays byte-identical in this plan. New there: `strings.json` and `models/string-spool.glb`. Never hand-edit `assets/`.
- `src/core` imports nothing from `src/styles`, `src/export` or `site`.
- No logos, wordmarks or string stencils, the spool included. Brand and string names are plain text.
- No fact from memory: a value no listed source states is left out (`shape: null`, a shorter list).
- Follow the design doc's **Research rules** exactly; they bind every worker and every request.
- At most two WebGL contexts. 375 px up, keyboard, reduced motion; lists, facts and search work without WebGL.
- Spool: at most 4,000 triangles and 40 KB; parts `spool` and `spool_string`; metres, Y up, base at the origin.
- British spelling in copy. Sounds at most 0.16, no pitch slides, off by default.

## Review Focus

1. **Old links.** `#/<racquet>`, `#/<racquet>/<colourway>`, `#/b/<brand>[/<line>]` all still open what they did. (Task 3)
2. **A string link that no longer exists** lands on the strings floor with a notice, not a blank page. (Task 3, Task 6)
3. **Tinting poisons the shared model.** Two spools on one page in two colours each keep their own. (Task 5)
4. **Search with strings not loaded** (slow or failed) still finds racquets and adds strings when they arrive. (Task 7)
5. **A white or black string's spool** is still readable on the pale wall and in all four looks. (Task 5)

```ts
export type StringMaterial = 'polyester' | 'multifilament' | 'synthetic-gut' | 'natural-gut';
export const STRING_RATINGS = ['power', 'spin', 'control', 'comfort', 'feel', 'durability'] as const;
export const STRING_TAGS = ['spin', 'power', 'control', 'comfort', 'durability', 'feel', 'value'] as const;
export interface StringSpec {
  id: string;                 // kebab-case, equals the file name, starts with the brand's folder name
  brand: string;
  name: string;               // without the brand: "ALU Power"
  material: StringMaterial;
  shape: { sides: number; label: string; twisted?: true; rough?: true } | null; // sides 0 round, else 3..12; null: no source says
  gaugesMm: number[];         // ascending, unique, each 1.0..1.45, at least one
  colours: Array<{ id: string; name: string; hex: HexColor }>; // 1-8, first is the default, ids unique
  finish: Finish;
  summary: string;            // 25-60 words
  bestFor: string[];          // 1-3 of STRING_TAGS
  ratings: Record<(typeof STRING_RATINGS)[number], number>; // integers 1..5, editorial
  compared: string[];         // 0-3 ids of other strings here
  confidence: 'high' | 'medium' | 'low';
  sources: string[];          // URLs, at least one
  researchedOn: string;       // YYYY-MM-DD
  verified: boolean;          // true once every colour was checked against a product photo
}
export const stringSpecSchema: z.ZodType<StringSpec>;
export function parseString(data: unknown, fileName: string): StringSpec;  // throws "<file>: <path>: <message>", as parseSpec
export function loadAllStrings(dir?: string): StringSpec[];                // Node only; sorted by brand, name, id
```
